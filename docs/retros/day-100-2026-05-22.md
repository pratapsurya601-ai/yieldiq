## 2. What worked

1. **The canary-diff harness is doing its job.** `scripts/canary_diff.py`
   plus the GH-Actions PR gate (per `CLAUDE.md`) caught regressions
   before merge on engine PRs. The 5/5 gate rule + 7 consecutive clean
   nightly runs as the "fixed" definition prevented the v32-v35-style
   regression cluster from repeating.
2. **Audit-driven prioritization beats opportunism.** Four numbered
   weekly audits (UX, SEO, monetization, canary restoration) plus
   three sector outlier audits produced ranked, dated work queues that
   directly seeded the next 10-20 Day-numbered tickets. Day-46 → Days
   47-50; Day-39 → Days 40-42 are clean examples.
3. **The Day-94 manifest replaced a recurring cost-amplification bug.**
   Day-95 was the first ship that used a scoped entry instead of a
   global bump; the manifest design doc names a ~13-hour-per-bump
   recompute cost as the trigger.
4. **Theme codemod in four small PRs, not one big bang.** PR-1 (825
   swaps) was the largest and merged cleanly because the surface was
   scoped to `(app)/` + `(stocks)/`. Splitting marketing, semantic
   components, and auth/legal into separate PRs kept review tractable.
5. **Test harnesses landed before the features that needed them.**
   Day-8 story-DCF back-testing harness predated the Day-9 frontend
   badge work; Day-77 vitest harness predated Day-87 frontend wiring
   of Day-76 backend additions.

## 3. What didn't work

1. **21 CACHE_VERSION bumps in 12 hours forced the Day-94 architectural
   fix.** This is the headline miss. The discipline rule in
   `memory/feedback_yieldiq_discipline.md` ("never bump unless you can
   name a ticker whose output changes") was not enough on its own —
   the right fix was structural, not behavioural. Should have been
   built earlier.
2. **Multi-render-path verdict-pill bugs.** Day-91 had to consolidate
   pill rendering into a single shared helper after audit #4 surfaced
   the same vocabulary slipping past in surfaces that had been missed
   in earlier passes. Three separate gates (Day-61, Day-91, Day-96)
   touched the same conceptual problem.
3. **SEBI-safe vocabulary repeat offenders in comments and chips.**
   "Strong"/"accumulate"-style words leaked through PR review more
   than once and had to be re-fixed in later passes. We do not yet
   have a lint rule blocking these phrases at the source level.
4. **Long-tail uncommitted worktrees.** `git status` on the retro
   branch shows 26 `yq-*` untracked worktree directories (foundation,
   fv-chart, peers, percentile, status-page-setup, several hotfix-*).
   Work-in-progress branches are accumulating without a clear policy
   for triaging stale ones.
5. **Day-94 verification is not yet closed.** We shipped the manifest
   but have not yet measured whether Railway memory / cost actually
   dropped vs the pre-Day-94 baseline. Day-95 used the manifest once;
   we need a follow-up measurement pass.
6. **Day-15 canary expansion target (333 tickers) is not yet reached.**
   The live canary file is 180 tickers. Sector coverage outside the
   top-cap names is still thin, which is why outlier audits keep
   finding new sub-buckets (logistics, hospital chains, regulated
   utilities, airlines).
7. **No real users yet, despite ≈100 days of build.** The Phase-1
   "5 paying users this week" target in `memory/project_yieldiq_roadmap.md`
   has not converted into a public push. Almost all 114 PRs were
   inward-facing engine, UX, or audit work.
